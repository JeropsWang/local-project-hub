# 配置契约 v1

这些文件是供评审的格式契约和虚构示例，不是已完成的应用实现。

## 文件

- [项目格式](project.schema.json)：可迁移的项目、运行方式、依赖、文件和运行单元。
- [工作空间身份](workspace.schema.json)：用户选定根目录下的 workspace.json。
- [导出清单](bundle.schema.json)：ZIP 内 manifest.json。
- [项目示例](examples/demo-bundle/project.json)、[清单示例](examples/demo-bundle/manifest.json)、[工作空间示例](examples/workspace.json)。

使用 JSON Schema 2020-12，格式版本固定为 1.0；未知版本拒绝，不猜测兼容。文件含 description 说明，源码生成时保留有意义的注释。

## 两阶段校验

Schema 负责结构、枚举、必需字段和禁止未知字段。业务校验继续检查下列关系，Schema 通过不等于可启动：

1. projectId 为稳定 UUID；unit、profile、requirement、file 的局部标识采用小写 kebab 名称；环境变量名独立采用字母、数字和下划线规则。
2. profile 引用、运行依赖和命令中的 runtime/file 引用必须存在；展开依赖后检查循环，禁用的可选功能不能被必需单元隐式引用。
3. 执行程序使用需求、绑定或内置系统工具标识，不将可迁移声明中的字符串当成本机绝对路径。
4. 参数只展开 file 引用；密钥通过本机 envBindings 解析，禁止把密钥值插入命令行或日志。环境变量名按 Windows 大小写不敏感规则检查冲突。
5. 引用文件、解释器、ABI、就绪与停止适配均需检查；stop=manual 或 managed 单元没有可验证停止策略时禁止全自动启动。
6. source.identity 为来源身份记录，不是用户可填写的“已验证”证明。实际提交、制品、文件哈希和本机绑定均重新核对。
7. 同一 resourceId 在多个项目中出现时比较完整服务需求与本机授权；不凭 ID 或名称自动合并。
8. 路径进入文件系统前检查根、父级、盘符、ADS、设备名、大小写/Unicode 冲突及重解析点，不能只靠 Schema 正则表达式。

## 原生状态与可迁移声明分离

项目 JSON 不包含源电脑盘符、当前 PID、容器 ID、密钥、本机接管权限或“已测试通过”标记。本机绑定、检查记录和运行实例保存在工作空间数据库中。

导入允许“配置有效、环境待补充”，但不能伪装为可启动。示例源码、数据库和密钥绑定都是虚构且未提供的，所以示例仅通过格式校验，不能直接启动。

## 包布局

```text
manifest.json
project.json
files/                按需携带声明的配置、脚本和自定义封面
```

清单 files 列出除 manifest.json 之外的全部文件，必须包含 project.json。projectId 与项目文件一致。未列明文件、重复路径及校验失败均拒绝；文件哈希覆盖原始字节，不包含自身清单。

示例清单中 project.json 的大小和 SHA-256 对应仓库中的真实示例字节。源码、EXE、镜像、模型及业务数据不进入首版包，声明为外部要求。示例不是离线完整包。

## 限额与默认策略

以下为首版工程默认值，可在未来版本显式调整，不静默放宽：

| 项目 | 默认值 |
| --- | --- |
| ZIP 文件大小 | 64 MiB |
| 累计解压字节 | 128 MiB |
| 单个文件 | 16 MiB |
| 文件数，不含 manifest.json | 2048 |
| 项目运行单元 / profile | 128 / 32 |
| 单个版本范围文本 | 512 字符 |
| 默认就绪 / 正常停止等待 | 60 / 30 秒，允许声明 1—300 秒 |

解压过程中累计实际字节，不能只信 ZIP 头。首版拒绝加密 ZIP、符号链接及其他非普通文件。压缩比不作为唯一拦截依据。
