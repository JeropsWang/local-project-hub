# 三个项目的接入验收

Windows 开发预览已经完成安装、覆盖升级和卸载验证。该验证使用临时目录和测试文件。管理核心的进程、Docker 和迁移测试也使用隔离数据。下表独立记录真实项目的验收状态。

| 项目 | 来源 | 当前状态 | 接入与验收 |
| --- | --- | --- | --- |
| PersonWeb | 用户选择的本地源码快照 | 已核对 Go 服务的信号退出入口与 Compose 文件布局，待隔离运行 | 对新建的 Compose 项目检查配置、端口、卷和环境绑定。用临时 PostgreSQL、Redis 和独立数据卷，验证完整启动、页面访问、日志定位及依赖逆序停止。已运行的实例只展示身份和来源线索。 |
| WeChatBot | GitHub v0.6.1，`0b6c7f4af00becb805e3bf6ecef6852e71741a2c` | 已核对 Fastify 关闭入口，待补管理协议 | 在独立分支把管理模式接入 `apps/server/main.ts` 和业务接单门禁。先暂停新任务，等待已接单任务，关闭本次创建的模拟桥接和 Fastify。验证等待、超时、重试及不确定发送状态，全程用模拟桥接。 |
| typing-tracker | GitHub v0.9.8，`ba61207ba3e8fd2621eb1538be46b56ed7b719a2` | 已核对托盘关闭与 `main.py` 的保存回调，待补管理协议 | 在独立分支把管道请求排队送到 Qt 主线程，复用采集停止和最终保存流程。存在未完成练习或保存失败时返回具体阻塞状态。用临时数据目录验证统计落盘和 GUI 进程实际退出。 |

三个项目均需在所选 Windows 机器上核对运行时版本、缺失文件和本机绑定。最后分别测试配置 ZIP 在空工作空间中导入、重新绑定、启动并安全退出。

WeChatBot 和 typing-tracker 的改动在各自 GitHub 发布提交上独立评审。PersonWeb 优先验证其现有 Compose 停止路径。评审通过后再执行对应的隔离运行验收。
