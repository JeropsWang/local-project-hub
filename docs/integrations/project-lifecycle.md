# 项目生命周期整合进度

当前为管理器核心实现与合成项目验证，尚未完成桌面入口、迁移包或三个真实项目的完整接入。

## 已有行为

- 启动计划先完成兼容检查，编译固定命令、工作目录、脚本内容及密钥引用，再执行选定配置的依赖顺序。
- 一次项目运行与每个本机进程分别持有独立身份。SQLite 保存不可变启动快照与独立的资源获取进度；外部操作开始前记录意图。
- 停止当前运行使用启动时的快照，配置的新修订不会替换它。进程仍以保留句柄和原始 Job 验证身份，容器仍需本机单独授权。
- 就绪检查支持进程、TCP、受认证控制协议状态，以及已登记 Docker 实例的健康状态。未知项目专用适配器明确阻止自动启动。
- 必需就绪检查失败会阻止后续单元启动；失败回滚只处理本次新获取的受管资源，保留已有外部引用。共享服务在单项目停止后保留，到全局退出最后处理。
- 退出期间关闭新任务准入，取消排队任务，在安全点等待准备结束。停止失败保留运行记录，返回等待用户状态；继续等待或重试恢复同一个任务，取消退出恢复准入，已经停止的项目保持停止。
- 只有全部受管运行及无人使用的受管公共服务正常结束，退出任务提交成功后，桌面入口才能通过 `CanQuit` 获准退出。关闭窗口应由后续桌面层隐藏到托盘，不调用退出协调。
- 脚本包装器的控制管道可由原始 Job 内子进程提供；发送控制令牌前验证实际管道服务进程的 Job 成员关系。父进程退出不能代表整个项目退出。
- 运行日志分页与轮转共用锁；Python 启动显式加入 `-B`，Go/npm/字节码缓存使用工作空间位置。

一次性任务区分 `checkpoint` 和 `wait`：前者使用可取消的临时 Job，后者使用不随调用取消而强杀的 Job，并核实所有成员退出。保存或迁移任务不会因为管理器的默认工具超时被结束。任务失败后的资源回滚不能撤销已经发生的业务数据修改。

## 验证与剩余工作
