# Windows 项目环境兼容与配置迁移设计草案

日期：2026-11-05。状态：用户已确认首版优先完整接入三个指定项目，Java、MySQL 等先提供检测报告；该范围作为后续设计和计划的基线。设计已完成实现者视角的完整性审阅；具体配置格式、模块接口和实现计划仍需细化，尚无应用实现。适用技术基线为 Go + Wails、React + TypeScript + Vite。

## 意图与范围

让用户在选定工作空间后，知道每个项目版本需要什么、目标电脑缺什么、如何修复，并可选择自动准备独立环境或只查看修复步骤。配置导入后必须能区分“文件完整”“环境满足要求”和“实际运行已验证”。

支持的目标类别包括 Vue、React、Next.js、Go、Python、Java 项目，以及 PostgreSQL、MySQL、Redis 和可选外部服务。首轮本机验收以 Windows 11 x64 为基线；其他 Windows 版本与 ARM64 的具体支持范围仍待验证，不因桌面框架支持就自动宣称业务项目兼容。

本轮只设计管理工具及其适配边界，不修改被管理项目，不操作真实微信、不迁移业务数据，也不把任意自定义脚本识别为可完全推断的程序。

## 候选方式与选择

| 方式 | 取舍 |
| --- | --- |
| 复制环境目录并执行一份通用安装脚本 | 速度直观，但不能可靠处理 Python ABI、绝对路径、DPAPI 和项目生命周期，不采用为通用机制 |
| 全部项目改造成容器运行 | 有利于部分服务封装，但现有 Windows GUI、桌面微信和输入钩子等场景需要本机运行，不作为统一前提 |
| 项目声明 + 环境探测 + 专用适配 + 独立环境 | 选择此方向；保存兼容条件和证据，通过不同运行方式的适配器执行 |

用户已确认两种环境处理模式并存、先初始化存放目录、关闭窗口继续运行和明确退出时安全停止项目。下文具体格式与默认策略为助手的设计建议。

## 项目描述与身份

项目可有多个运行 profile，例如开发、现有容器部署、源码运行、已打包桌面程序。每个 profile 保存：

- 稳定 projectId、profileId，来源种类、提交／源指纹、锁文件摘要。
- 运行位置：Windows 本机、指定 WSL 环境或指定 Docker 引擎；不能混合判断不同位置的 PATH 和依赖。
- 运行单元及依赖图，区分进程、任务、容器、外部服务及可选功能。
- 可执行程序、参数数组、工作目录、环境变量来源、就绪探测与停止策略。任意 shell 字符串单独标明解释器及版本。
- 兼容条件及来源、文件清单、外部路径绑定、必需配置名、数据 schema 要求。
- 资源控制关系：本工具管理、显式接管或仅引用；共享服务引用单独记录。

源码与运行实例分别建模。Docker 归属建议使用引擎身份、Compose 项目和 service 标签定位，再记录当前容器 ID。Docker 标签指向的工作目录与所选源码不一致时，只读显示差异，阻止自动重建，要求先绑定正确 profile。

## 兼容条件与证据模型

每项条件记录组件、运行位置、必需／可选、版本表达式、架构／ABI、必要能力、证据来源与更新时间。

版本表达式保留各生态语义：Node 按 npm semver，Python 按其版本与依赖规范，Go 按 go.mod/go.work/toolchain，Java 按 toolchain、release 与构建工具规则。不能用一个简单字符串大小比较代替。

最低版本、上界、排除项和可选分支均需支持。声明范围、元数据交集、CI 配置选择、本机实际观察及真正测试通过分别保留。CI 文件不等于 CI 成功记录，当前电脑能运行也不能推出最低版本。

检查结果与运行状态分离：

| 维度 | 结果示例 |
| --- | --- |
| 包／配置 | 有效、格式不支持、缺文件、校验失败 |
| 环境 | 满足元数据、缺失、不兼容、需绑定、未知 |
| 证据 | 项目声明、元数据核对、启动验证、桌面实机验证 |
| 运行 | 未准备、准备中、已准备、启动中、已就绪、停止中、失败 |

必需条件未知或不兼容时，禁止自动标为可启动；配置仍可在有效前提下登记为待补充。可选功能缺依赖只影响该功能。未执行的检查标记未验证，不能显示成功。

## 各类检测器

| 类别 | 静态读取与本机检测 | 准备策略 |
| --- | --- | --- |
| Vue / React / Next.js | package.json、实际锁文件、Node 与包管理器；分开开发、构建与运行依赖 | 固定 Node 与包管理器，使用锁文件；不以框架名称给全部项目统一版本 |
| Go | go.mod、go.work、toolchain 与本机 Go；区分源码构建和预编译运行 | 构建时选定工具链及模块缓存；运行既有二进制／镜像不强制安装 Go |
| Python | requires-python、requirements/锁文件、传递依赖元数据、解释器路径、wheel 标签 | 在目标位置重建环境，记录解释器和 ABI；不复制 venv、.deps 或二进制依赖当作通用迁移 |
| Java | pom.xml、Gradle toolchain、wrapper、编译目标及 JAR／class 元数据 | 分清 JDK 构建与 JVM 运行要求；未找到项目声明时报告未知 |
| 数据服务 | 镜像摘要、服务器版本、扩展、角色、schema 及所需能力 | 固定实例或镜像；大版本与扩展不满足时新建兼容实例或人工迁移，不就地自动替换 |
| 桌面／外部服务 | 交互式用户会话、客户端构建、必要接口、资源文件与可选功能 | 复用用户已登录客户端；不自动登录、重启或控制外部应用来伪造检测成功 |

普通检测仅读取静态声明和工具内置的只读探测，不执行安装钩子、项目脚本、初始化或迁移。自定义探测脚本作为另行执行的项目动作，明确展示其影响。

## 已核实样本对规则的要求

WeChatBot 声明 Node >=22.19.0；正式锁文件在 Windows x64 适用范围的 159 项 Node engines 中，静态样本比较发现 22.19.0、24.0.0、26.0.0 满足，23.0.0 和 25.0.0 因已锁 Vitest 的范围不满足。这里只是依赖元数据比较，不是应用运行认证。首轮准备基线建议 22.19.0，Python 桥接按 README/CI 选择 3.12.x。

typing-tracker v0.9.8 的发布配置选择 Python 3.13 x64。虽然 README 写 3.10+，锁定的 NumPy 2.5.3 要求 >=3.12，PySide6 6.11.2 要求 >=3.10,<3.15。因此建议 3.13.x 为首轮准备基线，不声称它是理论最低版本；完整传递约束和运行仍需验证。安装版 profile 不要求用户额外安装 Python。其默认运行使用 SQLite，可选 SearXNG 不得被当成必启容器。

Vue、Next.js、Java 与 MySQL 仍需真实项目样本才能批准具体版本范围。它们属于计划支持的检测类别，不标记为已验证适配器。

## 工作空间与自动准备

用户先选择磁盘和根目录，通过权限、空间及已有内容检查后初始化。运行时版本可共存，项目依赖保持独立；本机路径与可迁移声明分开保存。

两种模式使用同一检查器和同一结果模型：仅检测模式给出定位与修复步骤；自动准备模式先展示准备计划，再执行支持的下载、环境创建和锁定依赖恢复，完成后重新检测。

普通项目优先复用明确绑定且满足要求的既有环境。脚本固定寻找项目内 .venv、.venv-image-match，或入口优先加载 .deps 时，不能承诺只改 PATH 就能迁移到外置目录。

建议首版对这类工程提供两种接入：原位置登记并检测／复用；或由用户选择在工作空间创建洁净项目副本，再按它的相对目录结构准备环境。原位环境不支持外置时，显示限制和选项，不覆盖原 venv、不改业务源码、不搬走原数据。目录链接适配暂不作为首版必需能力。

准备计划区分只读检查、下载、安装、启动基础服务、构建、初始化和数据迁移。不能因为参数叫 NoStart 就把会启动容器的脚本当作完全无启动行为。自动准备模式不授权未知的数据库升级、客户端控制或强制终止。

安装需固定解释器、包管理器、下载来源和制品校验。普通导出包不承诺离线启动；只有依赖、镜像、wheel、资源和对应平台全部齐备并经过检查后，才可单独标记离线完整。

## 容器与公共服务

Compose 标签有助于发现归属，但不能证明业务层共享关系。没有归属标签的历史实例进入待认领清单，不按名字猜项目、不自动删除。

共享是显式关系。PostgreSQL 17 + pgvector 与普通 PostgreSQL 18、Redis 7 与 Redis 8，不因同类服务而自动合并。即使版本满足，仍需确认数据库、角色、队列前缀、配置和其他使用者；镜像存在或容器 healthy 不代表这些条件已通过。

镜像标签仅作显示，迁移与复现应记录摘要和平台。容器卷与宿主目录分别处理，选择工作空间不移动 Docker 虚拟磁盘或命名卷。数据库大版本升级须另走备份与迁移流程，不把数据目录直接挂到不同大版本作为自动修复。

## 导出、导入与身份绑定

包包含格式版本、项目与 profile 身份、依赖要求、文件清单、大小与 SHA-256。文件按随包携带、外部提供或步骤生成分类，脚本动态读取的额外文件由项目显式声明。

导出检查 Compose 引用、配置、脚本、资源、词库、schema 及构建产物的分类。随包项收集并校验，完整源码和制品等外部项列明必需绑定及指纹，不能只复制入口文件或把外部项假装已携带。真实密钥不进入默认配置包，机器和用户绑定凭据列为目标端重配项。

导入先检查格式和文件完整性、路径越界、资源限额，再选择目标目录和绑定关系，生成环境报告；导入本身不执行脚本。包文件损坏拒绝导入，外部依赖缺失则允许保存待补充登记。配置与环境完成验证后才进入准备／启动操作。

WeChatBot 使用 DPAPI CurrentUser；跨电脑复制密文不保证可解密。首版默认采用目标端重新配置密钥，不尝试读取和解密用户真实密钥来生成明文迁移包。

数据备份与配置导出分开。schema 版本、升级和回退路径分别记录；应用版本回退不等于数据库可降级。任何恢复失败保留原文件与已登记状态，不静默覆盖已有项目。

## 生命周期与安全退出

关闭窗口留在托盘，Go 核心继续负责实际状态和日志。明确退出时，停止接收新任务，处理在途操作，按依赖倒序停止项目，再处理由本工具管理且不再有其他使用者的公共资源，保存结果后退出。

管理器启动的 profile 必须具备可验证停止策略。仅引用的客户端和外部服务不自动纳入终止范围。停止策略包括项目正式停止接口／命令、正常退出等待、进程及资源状态核实和超时处理；不能只杀父进程或以端口消失当作所有数据已保存。

Windows 不能把发送某个信号、关闭窗口和应用正常退出视为同一操作。typing-tracker 的普通关窗会进入托盘，现有 CLI 未发现通用退出入口，因此需要单独设计并验证安全退出适配。适配未完成时只读登记或等待用户手工退出，不把强杀作为正常路径；原项目若需新增控制接口，单独安排实现。

WeChatBot 停止时需先暂停工作和桥接，不能结束用户微信。应用自身停止后再处理其专用基础服务。停止失败或超时显示具体未完成项，允许等待、重试或明确强制操作，不能提前报告全部停止。

本设计覆盖正常明确退出。系统强制结束与断电不能保证完成清理；再次打开先核对实例身份与实际状态，不能凭旧 PID 接管或结束新进程。

## Go 分层落点

按 `engineering-conventions.md` 实现：domain 保存条件、证据、profile 和关系模型；application 保存发现、检查、计划、准备、导入与停止用例；ports 定义探测、安装、进程、容器、归档和存储接口；adapters 实现生态与 Windows 差异；Wails 服务负责调用和结果映射。

界面负责展示来源、差异、检查报告和用户选择，不重复维护第二套版本判断。核心事件和日志使用有界缓存及明确顺序，隐藏窗口不取消后台任务，取消准备也不自动取消已提交的数据迁移。

## 验收与尚未完成的工作

实现前需锁定包格式与接口，验证以下场景：

- 同名／同版本号的分支、标签、工作树与运行实例不同，能分别记录并阻止误重建。
- Node 的区间、排除分支及锁文件变更触发重新检查；元数据通过不会冒充运行认证。
- Python 解释器、ABI 或项目内依赖覆盖不匹配时有准确原因；两个 Python 版本可共存。
- 缺文件、校验失败、路径越界、外部配置缺失和新格式版本分别处理，失败不破坏已有登记。
- 未选图像或搜索功能时，不安装其模型、不强制启动可选容器。
- 共享服务版本或命名空间冲突不自动合并，停止项目不影响未接管资源。
- DPAPI 跨机器迁移明确要求重配，不把旧密文当成可用密钥。
- 自动准备使用用户选定位置；只检测模式不安装、不启动、不写数据库。
- 托盘驻留、重复启动、停止超时与正常全局退出在隔离环境验证；真实微信实机操作另获明确授权。

具体库、非关键文件命名、内部错误码和测试夹具可由实现者决定；不能据此改变上述范围和行为。完整数据库迁移器、任意语言自动识别、离线全量打包、通用桌面应用退出注入不属于首版默认承诺。
