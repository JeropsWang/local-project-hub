# 工作空间初始化与环境处理

日期：2026-11-05。状态：需求和建议记录，不是已批准的实现设计，尚无对应功能代码。

## 已确认的决定

- 采用独立桌面程序，首版只支持 Windows。
- 检测目标电脑环境，并明确各项目版本的启动条件。
- 用户可选择自动准备项目独立环境，或仅查看检测结果与修复步骤。
- 准备环境前，用户必须先初始化并指定存放环境的磁盘和文件夹。
- 关闭管理器窗口后，已启动项目继续在后台运行。

## 初始化建议

让用户选择工作空间根目录，检查目录可读写、磁盘可用空间及路径是否适合管理。新建工作空间与打开已有工作空间应分开处理，不能覆盖已有内容。不默认在 C 盘安装项目运行环境。

建议根目录保存一个带格式版本和工作空间标识的描述文件。目录以用途划分：项目登记与配置、项目独立环境、受管理的运行时版本、缓存、日志和临时导入文件。导出及备份目标允许单独选择。

项目源码建议支持保留原位置，通过绑定路径登记；导入或新建项目时可以选择复制到工作空间，不能因为登记已有项目就自动移动源码。这些路径行为尚待确认。

初始化只创建约定目录与描述文件，不立即下载安装运行环境。首次启动某项目或准备导入项目时，再按项目要求检测与准备。

工作空间路径在本机配置中保存。迁移包使用路径变量，目标电脑初始化工作空间后重新绑定，不继承源电脑盘符。更改工作空间目录需要校验和环境重建流程，不能仅修改设置中的路径字符串。

## 两种环境处理模式

| 项目 | 自动准备独立环境 | 仅检测和修复说明 |
| --- | --- | --- |
| 环境检测与兼容判断 | 执行 | 执行 |
| 显示缺失项和准备步骤 | 显示 | 显示 |
| 创建项目环境、恢复依赖 | 用户选择该模式并启动准备后执行支持的步骤 | 不自动执行 |
| 未支持的安装步骤 | 给出原因及人工处理方法 | 给出人工处理方法 |
| 准备后重新检测 | 执行 | 用户修复后可重新检测 |

自动准备不能等同于任意系统配置都自动修复。建议优先支持用户选择目录中的项目环境和运行时；Docker Desktop、WSL、驱动、系统功能等另行检测，说明必要系统变更和是否需要安装、重启。

不因一个项目需要旧版本就降级全局运行环境，也不自动升级公共数据库。公共服务版本冲突需显示受影响项目，再选择兼容实例或调整项目配置。

导入与自动准备应分开：先识别校验，再选择准备模式，准备完成后验证，最后由用户启动。安装依赖和初始化任务可能执行代码，不能将它们描述为只读检测。

## 版本与能力判断建议

每个项目版本保存独立的运行要求，包括版本范围、架构、必要能力、执行位置和依赖锁文件。版本条件允许最低版本、上界与明确排除项。

分别保存声明支持范围、实际验证通过的环境组合以及未知项。当前电脑运行成功，不能反推出项目的最低支持版本。没有要求声明时可从项目文件读取候选条件，缺少依据的部分标记待确认。

本机检测到同一语言的多个安装位置时，记录实际使用的解释器及版本，不能只检查 PATH 中第一个命令。

Python 环境建议依据 Python 版本和锁定依赖在目标位置重建，不直接搬运 `.venv`。PowerShell 脚本需声明解释器及版本；本机与 WSL 内部运行环境分别检测。

建议将准备流程保存为有前置条件、可重复执行的步骤，区分检查、下载、安装、初始化和健康验证；失败时保留日志，仅清理本次创建的临时文件，不破坏已有项目。

## 关闭窗口与后台运行

用户已确认关闭管理器窗口后项目继续运行。建议首版关闭窗口后保留托盘入口，让运行核心、进程管理和日志采集继续工作，再次打开窗口连接现有状态，避免重复启动项目。

关闭窗口、真正退出应用、应用崩溃和系统重启是不同事件。当前决定只覆盖关闭窗口，不推断为后面三种情况也要求项目持续运行。

如果仅需要关闭窗口继续运行，可以先采用托盘常驻应用；若还需要界面应用完全退出或崩溃后继续管理项目，则需评估独立后台执行进程。后台进程是用户会话内进程还是 Windows 服务，仍需结合实际要求选择。

无论选哪种结构，都应明确哪些进程由本工具管理，且停止项目是显式操作。Docker 容器与本机进程的生命周期不同，需要分别记录，不能把界面关闭等同于项目停止。

## Docker 数据位置的边界

选择工作空间目录，只决定本工具管理的文件位置，不会自动搬迁 Docker Desktop 的镜像、命名卷或虚拟磁盘。

必须分别展示工作空间路径、绑定挂载的宿主机路径和 Docker 管理的卷。命名卷由 Docker 管理；不能把它显示成工作空间中的普通目录。若后续提供 Docker 数据迁移，需要按其后端支持的方式独立设计。

参考：[Docker volumes](https://docs.docker.com/engine/storage/volumes/)、[Docker Desktop settings](https://docs.docker.com/desktop/settings-and-maintenance/settings/)、[Python venv](https://docs.python.org/3/library/venv.html)、[PowerShell 版本差异](https://learn.microsoft.com/en-us/powershell/scripting/whats-new/differences-from-windows-powershell)。

- 自动准备首批支持的语言和依赖管理工具。
- 项目源码保留原位置或复制的具体选项。
- 真正退出管理器、异常退出和系统重启后的服务生命周期；关闭窗口继续运行已确认。
